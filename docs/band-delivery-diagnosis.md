# 手环送达诊断（静态说明，非验收）

本文件是**静态说明**，只描述怎么读手环探针页面上的四行诊断并原样回报。
本文件**不执行任何设备操作**，**不写入任何构建哈希**，**不声明任何实机成功**。
所有未由用户实测回报的项一律是 `unverified`：`unverified` 表示**没有取得对应证据**，
既不表示通过也不表示失败。

## 1. 已安装包的已核实事实（不改写成成功）

| 字段 | 值 |
| --- | --- |
| 包名 | `com.minavigatering.probe` |
| SHA256 | `eed0ba72154636ce4057768ab7542962fd7b8c5c3a78d826ab424e6a54236756` |
| 手环观察 | 显示「连接中」 |
| 送达 | `fail`（未显示左转200米） |

用户在手机通道任务成功之后打开该包，页面仍显示「连接中」，
没有显示「左转200米」。因此**手环侧的导航送达仍然是 fail**，回执也**没有取得**。
本文件**不得**把这个包写成已送达、也不得把手机通道任务成功当成手环回执。

## 2. 本诊断包的身份（不是别的验收）

本诊断包只把版本升到 `versionName=0.1.2-diag` / `versionCode=3`，并在页面上加了四行诊断文本。
它**不是** W-624 的图标验收包：图标是否随版本重装出现由 W-624 单独立项判断，
本诊断包**不声明**图标已修复或图标验收通过。

## 3. L3 安装前必须做的事

1. 在仓库根目录运行构建并读取 `band-app/dist/rpk-build-record.json`。
2. 用记录里的 `sha256` 核对 `diagnosticRpkPath` 指向的文件字节一致（构建产物与哈希只出现在
   `band-app/dist/`（gitignored）与 stdout，本文件不记录哈希）。
3. 核对记录里的 `versionCode` 为 `3`、`versionName` 为 `0.1.2-diag`。
4. 只有核对通过，才把 `diagnosticRpkPath` 交给用户安装。
5. 安装与卸载由用户/L3 按既有流程执行；本单**不运行 adb**、不安装、不卸载、不动签名。

## 4. 用户只需读四行并原样回报

打开探针页面后，标题「连接中」下方**始终**有四行，逐行原样回报即可（不要改写、不要推断）：

| 行 | 页面前缀 | 可能取值 |
| --- | --- | --- |
| 第 1 行 | `ready ` | `未探测` / `1已连接` / `2已断开` / `ready:<数字>` / `ready调用失败` / `诊断不可用` |
| 第 2 行 | `诊断 ` | `未探测` / `0对端已连接` / `204超时` / `1001对端未安装` / `1000其他` / `diag:<数字>` / `diag调用失败` |
| 第 3 行 | `入帧 ` | `0帧` 或 `string`/`object`/`other`，能读到 id 时附加 ` id=<值>`，解析抛错时为 `解析失败` |
| 第 4 行 | `链路 ` | `无` / `open` / `close` / `error` |

`入帧` 只记录帧**类型**与 `id`（摘要截断到 48 字符），**不记录整帧内容**，因此不会展示路线原文。

## 5. 四种组合怎么读（照实回报，不下结论）

| 组合 | 字面含义 | 说明 |
| --- | --- | --- |
| `入帧 0帧` + `诊断 1001对端未安装` | 对端（手环应用）未被认出 | 手环没有把该应用认成对端，帧到不了本应用。 |
| `入帧 0帧` + `诊断 0对端已连接` | 连接在，但没收到帧 | 链路是通的，只是本应用一帧都没收到；手机侧可能没发到这条通道。 |
| `入帧 string id=probe 消息` 但仍显示「连接中」 | 帧收到了，标题没更新 | 要么帧被显示逻辑清掉（例如随后收到心跳/断链事件覆盖），要么心跳只刷新存活时间、**不更新标题**（既有行为，本单不改）。 |
| `ready 2已断开` / `链路 close` / `链路 error` | 链路已经断开 | 页面按既有行为回到「连接中」；这不是送达证据。 |

以上都是**读法**，不是结论。任何组合都**不构成**手环回执或实机送达 pass。

## 6. 边界与口径

- 实机结果在用户回报之前一律是 `unverified`；本文件**不写** pass。
- `连接中`、`0对端已连接`、`1已连接` 只描述链路/宿主状态，**都不是**导航送达。
- 手机通道任务成功、构建成功、`diagnosis` 单测通过，
  **都不得**写成手环收到或手环回执。
- 只有在页面上出现对应**已发送 id 的回执**时，才能记手环确认；本诊断包本身不新增回执通道。
- 本文件不记录私钥、账号密钥或任何原始路线文本。
