# 手环拉起实验说明（实验 · 未验证）

本文件说明一个**手动实验**怎么做、记录在哪、记录怎么读、用户要盯什么。
本文件是静态说明，**不执行任何设备操作**，也不代表任何候选已经通过或已经失败。

## 1. 目的与状态

- 目的：手动试一下诊断页上的实验入口，能不能把手环上的“导航环”页面拉起来，并看这一次尝试记录到了什么。
- 状态：**实验、未验证**。
- **没有接进导航流程**：导航桥的命令和提醒不调用这个实验入口，实验成不成功都不影响导航主流程。
- 结论边界：本文件里的四种读法只描述“这一次尝试记录到什么”，不构成“拉起可行”或“拉起不可行”的结论。
- 关于本工作项本身的说明，逐字如下：

本工作项没有运行 adb、没有设备输出，不宣称拉起可行；PROJECT_SPEC.md 的页面入口规定未改

## 2. 怎么跑

前提（三项都成立才跑，缺一不跑）：

1. 手环已连：手机与手环的正常通道在诊断页上显示正常。
2. 手环上已装“导航环”。
3. 诊断页的“设备管理权限”显示已授予。

操作顺序：

1. 先让手环上的导航页**退出，回到表盘**，这样“页面本来就开着”不会混进本次记录。
2. 在诊断页点按钮 **“拉起手环导航页（实验）”**。
3. 候选按固定顺序逐个尝试；**每个候选之间停 4 秒**，等这一个落定、屏幕上稳定下来，再看下一个、再做记录。
4. 每一个候选都要单独记录（见第 5 节），不要只看最后一个。

## 3. 记录在哪

- 诊断页的**结果块**：每次尝试一行，按候选顺序排列。
- adb 侧：`adb logcat -s MiRingWearLaunch`，同一批尝试行也会出现在这里（本条命令由执行者自己按需运行，本工作项**没有运行**过）。
- 探测帧的发送和回执仍看 **MiRingTimeline** 的 **FRAME_SENT / ACK_RECEIVED**：这两类只说明应用层通道收发，
  **不等于**页面被拉起，不要拿帧计数当拉起证据。

## 4. 怎么读

| 记录 | 含义 |
| --- | --- |
| `task=ok` 且 `ack=yes` | SDK 接受了这次调用，并且手环应用开始应答。 |
| `task=ok` 但 `ack=no` | SDK 接受了，但手环没应答；页面没被拉起，或者没有应答通路。 |
| `task=fail` | SDK 拒绝；后面跟异常类名（只有类名，没有异常正文）。 |
| `pre-ack=yes` | 页面本来就开着，这次记录**作废**，不能算作一次拉起。 |

四种读法都只是这一次尝试的记录形状，不要外推成可行或不行的结论。

## 5. 用户要盯什么（每个候选都要单独记）

对每一个候选，逐项记下：

1. 手环**是否亮屏**。
2. 手环**是否打开了“导航环”页面**。
3. 手环**是否震动**。
4. **是否打断了别的页面**（原来开着的页面是不是被顶掉、被切走）。

四项按候选逐个记录，附上这次看到的记录行（第 3 节）。看不出来就写“看不出来”，不要补推测。

## 6. 不做的事

- 不改 `PROJECT_SPEC.md`，不改页面入口规定。
- 不把实验记录当作导航流程已接入，也不当作实机验收。
- 不记录节点 id、账号、密钥、通知正文、签名材料。
