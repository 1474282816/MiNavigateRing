# 自动拉起手环导航页（手机端 · 未在真机验证）

本文件说明“导航开始时手机自动拉起手环导航页”这个功能做什么、什么时候触发、什么时候不拉起、
开关在哪、日志怎么读，以及目前已知的限制。本文件是静态说明，**没有运行 adb、没有设备输出**。

## 1. 功能

高德导航会话开始时，手机自动调用一次拉起，把手环上的导航环页面 `pages/index` 打开，
用户不必先手动打开手环页面。

本功能**只做手机端**：手机端判断要不要拉起，然后调用一次官方 SDK 的拉起接口。
手环端页面本身不需要为这个功能做任何改动，手环上装的仍然是原来的导航环页面。

## 2. 触发规则

- 触发信号：监听器认定的高德导航通知**从没有变成有**（`ProbeRuntime.wakePolicy.amapNavigationPresent`
  的上升沿）才算一次导航会话开始。下降沿、通知内容更新、通知数量变化都不算开始。
- 每次会话**最多成功拉起一次**；已经拉起过的会话里再出现的通知更新不会重复拉起。
- 拉起成功后约 3 秒再发送一次最新内容，避免手环页面刚打开时停在空白或上一次的旧内容上。

## 3. 结束规则

以下三种情况算导航会话结束，结束会清除“本会话已拉起”的记录：

1. 解析出**明确的导航结束**。
2. 导航通知被移除，并且过了移除宽限 `AmapCloseout.REMOVAL_GRACE_MS` 到期后**仍然没有**
   任何被跟踪的高德导航通知。
3. 通知监听断开：`onListenerDisconnected` 与 `onDestroy` 两条路径都算结束。

补充说明：

- 重新规划路线造成的“几秒内移除、随后又重发”**不算结束**，移除宽限就是为这种情况留的。
- 用户在导航中途自己关掉手环导航页，**不会**再拉起。本功能只负责会话开始那一次；用户关掉页面
  被当作明确的用户意图，手机端不与他抢页面。

## 4. 五种不拉起的情况（判断顺序固定）

判断按下面的顺序逐条进行，命中第一条就停：

| 顺序 | 记录名 | 含义 |
| --- | --- | --- |
| 1 | `SETTING_OFF` | 诊断页的自动拉起开关是关的 |
| 2 | `BRIDGE_OFF` | 导航桥是关的 |
| 3 | `NO_NODE` | 当前没有可用节点 |
| 4 | `PAGE_ALIVE` | 近 20 秒内有手环回执（`ackAgeMs` 不为 null 且不大于 20000），说明手环页面本来就在运行 |
| 5 | `ALREADY_LAUNCHED` | 本会话已经拉起过一次 |

关于顺序和状态的约定：

- 顺序固定，不能因为“看起来更合理”而调整；调整顺序会改变用户看到的行为。
- 只是被跳过**不算**已拉起：条件不满足时不会记成已拉起，等条件满足后该会话仍然可以拉起一次。
- 拉起失败**只记录，不重试，不弹窗**。失败不消耗“本会话已拉起”的记录之外的重试机会，
  也不会因此反复骚扰用户。

## 5. 开关

- 开关位置：**诊断页**。
- 默认状态：**开**。
- 主页没有这个开关。主页是导航主流程，不放这类实验性设置；想关掉自动拉起时到诊断页关。

## 6. 日志怎么读

日志标签统一是 `MiRingWearLaunch`。自动拉起相关的是 `auto` 开头的行：

| 行 | 含义 |
| --- | --- |
| `auto launch ok` | 这一次拉起调用成功。 |
| `auto launch fail:<异常类简名>` | 拉起调用抛异常，后面只有异常**类名**，不含异常消息正文。 |
| `auto skipped:<reason>` | 本次该拉起但被跳过，`<reason>` 是第 4 节表格里的记录名之一。 |
| `auto not-installed` | 手环上没有装导航环应用，因此不拉起。 |

日志里**不记节点 id**，也不记通知正文、路名或账号信息，所以这些行可以直接收集作为交付证据。

## 7. 已知限制

以下限制是当前实现的真实状态，不是待办清单：

- **会顶掉手环上正在看的别的页面。** 拉起是直接切到导航环页面，不询问用户；如果手环当时在别的页面，
  那个页面会被切走。
- **手环熄屏时不会自己亮屏。** 拉起只负责打开页面，不负责点亮屏幕；屏幕不亮时用户看不到变化。
- **没有观察到震动。** 拉起这个动作本身不伴随震动，也没有观测到拉起引发的震动。
- **两项尚未实测。** 手机长时间空闲后从后台发起的拉起，以及手环正在运动记录中的表现，
  都还没有实测结果，不能推定可用或不可用。
- **进程重启后会话状态丢失，可能再拉起一次。** “本会话已拉起”的记录只在内存里，
  手机进程重启后就没有了；如果此时导航仍在进行，下一个导航信号可能再拉起一次。

## 8. 验证边界

本工作项没有运行 adb、没有设备输出，不宣称自动拉起已在真机通过。

本文件描述的是代码里的规则和已经写下的限制，不是真机观测记录。真机上的拉起结果、亮屏、震动、
被打断页面的实际表现，都还需要单独的设备验证，并且要能对应到具体的设备与版本。
