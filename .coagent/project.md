# MiNavigateRing 平台项目约定

## 需求与设计基线

先读 `PROJECT_SPEC.md`；手机与手环界面、颜色和矢量资源见 `design/design-data.json`，动作语义见 `design/NAVIGATION_ICONS.md`。设计预览是样稿，不代表设备能力已经通过验证。用户已于 2026-10-12 授权使用 CoAgentHub 实现；协调者不在本文件固定，按平台资源池当前顺序派发（用户 2026-10-15 指定 GPT-6.1 Sol 排第一、Grok 4.7 其次）。当前票先完成构建与通信探针，再验证实机技术关卡。

## 三层分工与派发

L3 是用户当前开着的检视者会话（Codex 或 Claude，现为 Claude），处理升级、核对合同验收并签集成分支合入。协调者 L2 按平台资源池当前顺序派发（用户 2026-10-15 指定 GPT-6.1 Sol 排第一、Grok 4.7 其次），不在本文件或契约里固定模型；L2 规划、拆分冻结工单并逐条验收，不因实际协调者与历史指定不同而升级，实际派发身份由 L3 在汇报里核对并写明。执行者 L1 使用平台当前健康候选实现。

集成目录为 `C:/program1/MiNavigateRing/.worktrees/integration`，集成分支为 `coagent/integration`，主目录保留 main。平台在 Mission 工作树（`C:/program1/MiNavigateRing/.worktrees/missions/<mission>`）内实施，交卷后由 L3 审查；主干合入需用户另行明确授权。单票累计费用到 $10 交用户决定。产品源码与测试以集成分支当前内容为准，引用文件前先确认它存在。

## 实施与验证顺序

先准备 Android 与 Vela 最小工程、官方通信 SDK 适配和消息探针，核实构建/安装渠道与后台能力；通道和后台关卡通过后才展开完整高德解析。SDK 与现有小米运动健康 3.59.1、手环9 NFC 固件3.1.32 的兼容性需要证据。手机型号 K90 至尊版；主机已有 adb 和 Android SDK，但本次检查 adb 未列出连接设备。

验证命令使用可直接执行的 argv，遵循平台禁用 shell 包装的门禁。Windows Gradle 构建优先使用 Java 调用 Gradle Wrapper 主类或已核实的可执行入口；不要将 `gradlew.bat` 外包 `cmd /c` 当作平台验证命令。无设备时可验证主机构建与协议测试，设备项标记 unverified 并提交可复现步骤与实测工具，不伪造截图、通知样本或后台结果。

## 执行者红线

- 仅实施冻结工单允许的路径；需求依据 `PROJECT_SPEC.md`，图标依据 `design/NAVIGATION_ICONS.md`。保持通知监听、解析、导航引擎、通信和手环渲染职责分离。
- 允许小米运动健康参与后台通信，不实现完全脱离官方 App 的认证接管；官方 SDK 或安装入口不可用时交付证据并升级。
- 先完成消息/后台技术关卡；没有证据时不把完整界面或模拟通信当作实机通道成功。收到无法识别方向时进入明确异常状态，不默认直行或推测环岛出口。
- 首版高德、步行与骑行；必要首次授权；手动选择模式并记忆；新转向与30/100米临近提醒各一次、距离更新静默；其余细节以项目规范为准。
- 保留现有手环绑定；设备安装应由实际授权路径执行，不解绑、不恢复出厂、不升级固件、不修改手机系统安全设置，不擅自接受许可协议。
- 账号、密钥、签名私钥、原始路线与私人日志保持本地且不入库；交付脱敏证据。SDK 依赖记录官方来源、版本与哈希，先核实使用/分发许可。
- 代码与验证产物在本项目工作树内；不修改 CoAgentHub 平台、适配层、其他项目、全局模型凭据或候选池。`.coagent/` 文档通过平台提议，不由 L1 直接改写。
- 测试验证真实行为和状态边界；没有高德实测通知时明确样例是合成夹具，不能用合成夹具宣称中文真实解析已验收。提交构建命令、输出产物、平台验证编号与逐项证据。
