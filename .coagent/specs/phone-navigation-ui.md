# 手机导航主界面

范围：手机端 NavigationScreen 的日常展示。内容由纯映射 `mapNavigationUi`（`app/src/main/java/com/minavigatering/probe/navigation/NavigationUiState.kt`）决定，屏幕只渲染它的结果。通知解析、传输、协议和手环渲染不在本规格内。

## 八个阶段

前五个阶段按优先级从上到下，命中即止；之后按状态区分。

1. 权限未开：通知读取权限没有授予。
2. 桥接关闭：导航桥开关为关。
3. 通知读取未连接：权限已授予、导航桥已开，但 `AmapNotificationService.isConnected` 连续为假达到 5 秒（`LISTENER_DOWN_GRACE_MS`；主屏每秒用 `SystemClock.elapsedRealtime` 累计，连上即清零，作为 `mapNavigationUi` 的入参 `listenerDownMs`，默认 0）。`isConnected` 只在系统调用 `onListenerConnected` 后为真，`onListenerDisconnected` 与 `onDestroy` 后清空，它反映监听器是否真的被系统连上，不是权限开关。标题“通知读取未连接”，提示请在通知读取设置里把“MiNavigateRing 高德导航”关闭再开启一次；该阶段不展示上一条有效指令，不自动打开设置页，不做重绑或自愈。
4. 通信连接中：前台会话没有运行，或传输层当前没有手环节点（`transport.currentNodeId` 为空，主屏每秒采样一次）。不读消息载荷里的 `link` 字段（手机侧构造的状态里它恒为默认的 connected），不用 SDK Task 成功或回执文本推断“已连接”；该阶段不展示上一条有效指令。
5. 等待导航：还没有状态，状态为空闲，或是手机刚重启恢复出来的状态（id 以 `restore-` 开头，常量 `NavigationSettings.RESTORE_ID_PREFIX`；那是手机从本地存档还原的占位，不含导航信息，不是故障）。
6. 导航已结束。
7. 信息暂不可用：状态为无法识别，或有效状态但动作为空、不在 14 个允许动作内（上面第 5 条的重启恢复状态除外）。说明按原因分三句，见下面“信息暂不可用的三种原因”。
8. 有效导航：动作在 14 个允许动作内。

## 有效导航显示什么

- 中文动作名（14 个，与手环图标一一对应）作为大标题；`left`、`slight-right` 等协议标识不上屏（模型里保留 actionId，供以后图标使用）。
- 距离：`N 米`；缺失显示“距离未知”；到达目的地不显示距离。
- 路名：有就显示；缺失（null、空、空白）时不占这一行。K90 的真实高德通知样本不含路名，不用“路名未知”之类占位，也不拿别的字段顶替。
- 环岛出口：只在“驶出环岛”显示，写成 `第 N 出口`；缺失显示“出口未知”。
- 当前模式（步行或骑行）。
- 未知动作不默认直行，不编造路名、距离或出口。

## 文案与引导

- 每个阶段只给一段面向用户的下一步提示：“通知读取未连接”先说明现状再给操作，共两句；“信息暂不可用”按原因写（用户 2026-10-22 定：原因全放手机端写详细，手环端不写原因），允许一到两句；其余阶段一句。写给审查者的约束语句，以及回执、SDK Task 之类概念不上屏，回执、错误和合成测试只在诊断页。
- “一次性设置”卡片（允许读取通知、后台设置）只在权限未开、桥接关闭、通知读取未连接、通信连接中出现；“通知读取未连接”时卡片里的“查看通知权限”按钮就是让用户去关闭再开启通知读取的入口。
- 等待导航的提示取决于“开始导航时自动拉起手环导航页”开关（`NavigationSettings.autoLaunchBand`，默认开，诊断页可关）：开着写“在高德开始步行或骑行导航，手环导航页会自动打开。”；关着仍是先在手环打开导航页、再在高德开始导航，这是用户首次使用必须知道的一步（PROJECT_SPEC“页面入口”：默认自动拉起，用户也可以手动打开）；有效导航中这类说明不常驻。

## 信息暂不可用的三种原因

标题仍是“信息暂不可用”，只有说明（guidance）按原因选一句，判断按下表从上到下，命中即止。`mapNavigationUi` 为此在最后再加两个带默认值的入参（默认 false，既有位置参数调用与既有测试不受影响）：`amapNavigationPresent`（高德导航通知此刻是否在显示，取 `ProbeRuntime.wakePolicy.amapNavigationPresent`）与 `autoLaunchBand`（取 `NavigationSettings.autoLaunchBand`），主屏每秒轮询时随其他输入一起读取。

| 条件 | 说明 |
| --- | --- |
| 状态是有效（active），但动作为空或不在 14 个允许动作内 | 高德给出的转向动作无法识别，手环不会显示猜测的方向。 |
| 状态是无法识别，且高德导航通知仍在显示 | 高德正在导航，但这条提示读不出转向方向。手环不会显示猜测的方向，请看高德或等下一条提示。 |
| 状态是无法识别，且没有读到高德导航通知 | 没有读到高德的导航提示：导航可能已结束，或高德已退出。要继续请回到高德重新开始导航。 |

手环端对应：手环只分“有导航”“暂无导航”“连接中”三种。空闲、导航已结束、信息暂不可用这三类统一显示“暂无导航”，原因不上手环（窄屏，用户 2026-10-22 定）；用户要知道为什么，看手机这一页。手环文字居中。手环三种显示与手机原句汇总在 `docs/state-copy.md`。

## 安全区、名称与桥/节点状态

- NavigationScreen 根布局在原有 `padding(24.dp)` 前使用 `safeDrawingPadding()`；应用与启动 Activity 的名称、页内大标题均为“导航环”，副标题“高德步行 · 骑行导航”不变。通知使用权服务标签与前台通知标题不受此命名变更影响。
- `Theme.Probe` 设置 `android:windowLightStatusBar=true`，状态栏时钟和电量用深色图标，避免白色图标压在浅色页面上看不清；主代码里没有 `enableEdgeToEdge` 等运行时覆盖，所以主题属性生效。
- `mapNavigationUi` 输出 `bridgeLine: String` 与 `bandLine: String?`，屏幕直接展示；计算只依据桥开关、前台会话和节点存在性，不改变八阶段及 guidance。

| 条件（按优先级） | bridgeLine | bandLine |
| --- | --- | --- |
| 桥关闭 | 开启后自动同步高德导航 | null，不展示 |
| 桥开启、会话未运行 | 导航桥启动中 | null，不展示 |
| 桥开启、会话运行、无节点 | 导航桥已开启 | 手环：未发现，正在连接 |
| 桥开启、会话运行、有节点 | 导航桥已开启 | 手环：已发现，尚未确认收到 |

节点存在只代表手机侧发现节点，ACK 未验证，上屏不宣称“已确认”“已连接”“已收到”。安全区真机遮挡改善与两行状态实际观感仍 unverified。

## 未验证

纯映射的单测和 Kotlin 编译只证明状态映射正确且可编译。主界面实际观感，以及手环实际连接和断连是否及时反映到主界面（`currentNodeId` 由前台心跳约每 5 秒刷新），仍是 unverified，不能当作完整首版实机通过。状态栏深色图标在真机上是否清晰，以及“通知读取未连接”阶段的真机表现（覆盖安装后是否出现、按提示关闭再开启通知读取后是否消失、冷启动 5 秒宽限是否足够、系统设置列表里显示的是服务标签“MiNavigateRing 高德导航”还是应用名“导航环”），同样 unverified。三句原因说明、新的等待句与“重启恢复按等待导航”在真机上的表现，以及手环文字居中和“暂无导航”的实际观感，同样 unverified，以用户装机观感为准。

## 视觉设计（2026-10-15 重设计）

范围：NavigationScreen 的视觉与布局。`mapNavigationUi` 的输入、八个阶段、文案与禁词规则不变，这里只规定怎么画；诊断页（“连接诊断与测试”）不在本节范围。

设计思路：浅色页面上放一张深色“手环镜像”主卡——黑底、手环同款绿色箭头、白色距离、青色路名、黄色出口，让手机上看到的就是手环该显示的内容；其余用白色卡片加细边框，主色深绿，警示用琥珀色。保持 `safeDrawingPadding()` 与状态栏深色图标（页面是浅色）。

### 结构（自上而下）

1. 标题行：“导航环”在左，当前模式小标签在右（取 `modeLabel`）。
2. 主卡（内容见下表）。
3. 状态卡：每行一个状态点加 `bridgeLine`、`bandLine`（`bandLine` 为空则只一行）。点的颜色由“桥是否开启且会话在运行”“节点是否在场”这几个布尔输入决定，不靠解析文案。
4. 设置清单卡：只在权限未开、桥接关闭、通知读取未连接、通信连接中显示。行：高德通知读取（已允许显示对勾加“查看”按钮，否则“允许”按钮）；后台运行不受限（用 `BackgroundPolicy`，已豁免显示对勾且不画按钮，未豁免显示“允许”按钮）；本应用省电策略与自启动（“打开”，进本应用的应用信息页）；小米运动健康后台不受限（“去设置”按钮）；若开机恢复失败过（`lastRestoreText` 以 failed 开头）再加一行提示“需要打开一次应用恢复同步”。
5. 模式选择：分段控件“步行｜骑行”，做成圆角胶囊——外层轨道（圆角 50%、底 #E4E9E6、内边距 3dp），两个选项各自圆角 50%，选中项主色底白字、未选中项透明底深色字，最小高度 48dp；行为与现在一致（写偏好，会话在运行时发 UPDATE）。
6. 主按钮：权限未开为“允许高德通知读取”（实心，打开通知读取设置）；通知读取未连接为“查看通知权限”（实心，同上）；桥接关闭为“开启导航桥”（实心）；其余为“关闭导航桥”（描边）。启停逻辑与现有一致，权限未开时开关保持现有的禁用语义。
7. 页脚：文字按钮“连接诊断与测试”加右箭头。

| 阶段 | 图标 | 标题 | 其他 |

主卡内容水平居中（和手环一致）：图标、标题、距离、路名、出口、说明都居中，说明文字多行时逐行居中；只有主卡顶部的小标题靠左。

小标题：有效导航写“手环上显示的内容”，需要处理的两个阶段写“需要处理”，其余不写。

动作矢量图标共 14 个，资源名 `nav_<动作 id，连字符改下划线>`，路径取自 `design/design-data.json` 的 `paths`（84×84 视口；left、right、straight 三个闭合箭头用填充，其余用描边，宽 9、圆头圆角）。`actionId` 找不到资源时按“信息暂不可用”画（不显示图标）。

### 不变量

- 所有屏幕文案仍来自 `mapNavigationUi` 的输出，禁词规则不变；新增的文字（清单行、按钮、小标题）也不得出现禁词。
- 权限与启停流程、1 秒轮询、`listenerDownMs` 计时、诊断页入口的行为不变。
- 视觉效果在真机上是否合意属 unverified，以用户装机观感为准。
